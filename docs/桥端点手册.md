# MC 桥端点手册（鱼鱼专用）

> 写给鱼鱼操作 BlueWhaleMaid 身体用。**每个示例都是 2026-11-08 实测真实返回**，不是猜的形状。
> 两个地址同一座桥：云上用 `http://127.0.0.1:47880`，PC 本地 `http://127.0.0.1:17700`。无认证。
> 路线：先 GET 读状态 → 想条件等待用 POST /wait → 要动手才 POST 动作（动作全串行，一次只跑一个）。

## 0. 全局铁律（先读这个，能省一半调试）

| # | 铁律 | 后果（不守会怎样） |
|---|---|---|
| 1 | **坐标是两位小数浮点，永远不许 `==`** | `pos.x == 72` 几乎永不成立。要写 `pos.x > 72.4 && …` 不行就拆两次 /wait，或 `> / <` |
| 2 | **动作失败=500，参数错=400；503 只给 GET** | POST 打到掉线的 bot 也是 500 `bot not connected`——500 不一定是"桥挂了"，先看 error 文本 |
| 3 | **503 = bot 掉线自愈中**（实测 25s 内回线；重连退避 5→10→20→40→80→160→300s） | 见 503 等 25s 重试；连续 300s+ 不恢复再报主持 |
| 4 | **中文只能走 node fetch / 程序内请求，curl 会 GBK 乱码** | 乱码会真的发进游戏聊天栏，所有人都看得到 |
| 5 | **动作串行队列**：/chat /dig /path /find /craft /equip /place 一次一个，自动排队 | 大批量动作会排长队；/wait 不占队列（等待不堵动作） |
| 6 | **/state 顶层没有 day 字段名之外的坑**：`time.timeOfDay` 是 0–24000 游戏刻不是小时；判天数用顶层 `day` 或 `/time` 的 `day` | 当"几点"比大小必错；6000=正午≈，18000=午夜 |
| 7 | 物品名/方块名**没有 `minecraft:` 前缀**，全小写下划线 | `minecraft:stone` 认不到 |
| 8 | MCP 工具失败是 **HTTP 200 + `isError:true`** | 按状态码分诊会把失败读成成功 |

## 1. GET 读端点（6 个，随时随便调，不排队）

### GET /health
```json
{"ok":true,"botConnected":true,"lastSpawnAt":"2026-11-08T03:31:05.734Z","uptimeSec":1411,"autoChat":true}
```
- **唯一没有 `{ok,data}` 包装的端点**（平铺）；连接态字段叫 `botConnected` 不叫 `connected`
- 用途：等 bot 回线 → `POST /wait {"path":"/health","condition":"botConnected == true"}`

### GET /state（全量快照，一次拿全）
```json
{"ok":true,"data":{"connected":true,"username":"BlueWhaleMaid","pos":{"x":72.5,"y":73,"z":-64.31},
 "health":20,"food":20,"saturation":5,"dimension":"overworld","gamemode":"survival",
 "time":{"timeOfDay":7353,"day":27},"day":27,"players":["BlueWhaleMaid"],"onGround":true,
 "heldItem":"stone_pickaxe","inv":[…],"invCount":{"dirt":16,"spruce_planks":11,…},
 "invSlotsUsed":5,"invSlotsTotal":36}}
```
- 键全集：connected/username/pos/health/food/saturation/dimension/gamemode/time/day/players/onGround/heldItem/inv/invCount/invSlotsUsed/invSlotsTotal
- `invSlotsUsed >= 36` = 背包满（总 36 格）；`day` 是顶层别名（判天数最方便）
- 掉线时：HTTP 503 + `{ok:false,data:null}`

### GET /pos
```json
{"ok":true,"data":{"x":72.5,"y":73,"z":-64.31}}
```

### GET /time
```json
{"ok":true,"data":{"timeOfDay":7353,"day":27}}
```

### GET /inv/count
```json
{"ok":true,"data":{"cobblestone":1,"dirt":16,"wooden_pickaxe":1,"spruce_planks":11,"stone_pickaxe":1}}
```
- 扁平 map：物品名→数量；**没列出的物品=0 个**（/wait 里 `iron_ingot == 0` 缺货也成立，v1.1 语义）

### GET /inv（数组版，细节用）
```json
{"ok":true,"data":[{"name":"cobblestone","count":1,"slot":36},{"name":"dirt","count":16,"slot":37}]}
```
- ⚠️ slot 36–44 = **快捷栏**（mineflayer 窗口编号），主背包 9–35
- /wait 条件面**不含** /inv（数组），要等数量用 /inv/count 或 /state.invSlotsUsed

### GET /landmark（地标列表，= recall）
```json
{"ok":true,"data":{"action":"recall","total":1,"max":24,"landmarks":[
  {"name":"小屋(hut_small)","x":43,"y":70,"z":-70,"dim":"overworld","distance":12.4,"mismatches":0}]}}
```
- 最多 24 处；**坐标是 floor 后的方块格，距离按真实位置算** → 站在自己地标上 `distance` 是 0.7 不是 0（别以为地标飘了）

### GET /job（作业进度 + 上一次的收尾报告）
```json
{"ok":true,"data":{"running":false,"type":null,"phase":null,"step":null,"last":{
  "ok":true,"type":"dig_shaft","report":"job dig_shaft completed: 深度 2 的阶梯矿井已挖好…","durationMs":10614,"step":2}}}
```
- `running=true` 时还有 `phase`（walking/checking/digging/clearing/building）、`step/maxDepth` 或 `placed/total`
- **收尾报告在 `last` 里，作业结束后一直在**，别只看 running

### GET /look（今日视觉配额）
```json
{"ok":true,"data":{"used":3,"limit":200,"minIntervalMs":2000,"day":"2026-11-08","cooldownMs":0},"viewerPort":3010}
```
- 只读，不花配额；用来判断"还能不能看"

## 2. POST 动作端点（串行排队）

### POST /chat `{"text":"你好"}`
→ `{"ok":true,"said":"你好"}`
- 缺 text → 400。中文必须 node fetch（铁律 4）

### POST /dig `{"x":76,"y":77,"z":-60}`
→ 成功 `{"ok":true,"data":{"dug":"spruce_log","at":{"x":76,"y":77,"z":-60}}}`
- **错误方向**：坐标非数字 → 400 `x,y,z numbers required`；够得着但不是方块/太远 → 500
  - `too far (>6 blocks)`——距离 ≤6 格（欧氏距离）
  - `no block there`——那里是空气（挖不存在的）
  - `dig timeout 60s`
- **挖不动的方块**（基岩/太硬）会超时；空手挖石头也能挖但极慢，先 /equip 镐

### POST /path `{"x":71,"y":75,"z":-64}`
→ `{"ok":true,"data":{"arrived":true,"pos":{"x":72.5,"y":73,"z":-63.5}}}`（GoalNear 半径 1 格）
- ⚠️ **`Took to long to decide path to goal!` ≠ 没走到**——寻路器偶发超时但身体实际移动了。**判定一律看之后 /state 的 pos**，别把这条错误当失败
- 超时 15 分钟；目标不可达会自己放弃

### POST /find `{"name":"stone","count":3}`
→ `{"ok":true,"data":{"query":"stone","hits":[{"x":61,"y":70,"z":-72,"name":"stone"},…]}}`
- 找**附近**方块（水平 ±12、垂直 ±3，按距离顺序，最多 64）
- 未知名 → 500 `unknown block/item: xxx`；附近没有 → `hits:[]`（不是错误，走远点再找）
- ⚠️ 搜树挖整根：hits 是同 name 的散点，同 x,z 不同 y = 一根树干

### POST /craft `{"name":"spruce_planks","count":1}`
→ `{"ok":true,"data":{"crafted":"spruce_planks","count":1,"usedTable":false}}`
- ⚠️⚠️ **count = 合成操作次数，不是产量**！木板 1 次=1 原木→4 块。要 20 块木板 count=5
- ⚠️⚠️ **大 count 会"missing ingredient"中途失败且网格卡渣**——永远小步（count=1~2）+ 每步 GET /inv/count 验证
- `usedTable:false`=2x2 配方免台；3x3 配方（镐/斧/台本身除外）需要**工作台在 4 格内**，缺台报 `no recipe for xxx（3x3 配方需要合成台在 4 格内）`
- **`no recipe` ≠ 配方不存在**——是"以当前背包料做不出"（缺料时查不到配方）。缺料先补原料
- 常见配方：spruce_planks(1 log→4) / stick(2 planks→4) / crafting_table(4 planks) / wooden_pickaxe(3 planks+2 stick) / stone_pickaxe(3 cobblestone+2 stick)

### POST /equip `{"name":"wooden_pickaxe"}`
→ `{"ok":true,"data":{"equipped":"wooden_pickaxe"}}`
- 背包没有 → 500 `not in inventory: xxx`。放方块前必须先 equip 目标方块

### POST /place `{"x":71,"y":75,"z":-65}`
→ `{"ok":true,"data":{"placed":true,"at":{"x":71,"y":75,"z":-65}}}`
- 放的是**当前手持**（先 /equip）；≤5.5 格
- 校验三连（不满足就 500，不会硬放）：
  - `too far (>5.5 blocks)`
  - `target not air: dirt`——目标格被占
  - `no support below`——下方悬空放不了
- 放工作台/门口封顶都靠它；支持物=目标格正下方那格

### POST /wait（条件等待，详见 §3）
### POST /mcp（工具面，详见 §4）

### POST /block `{"x":43,"y":71,"z":-70}`
→ `{"ok":true,"data":{"name":"spruce_planks","at":{"x":43,"y":71,"z":-70},"diggable":true,"boundingBox":"block","hardness":2}}`
- **/find 是"名字→位置"，这条是"位置→名字"**：验房子对不对、看脚下/头顶是什么，全靠它
- 区块没加载 → 500 `block not loaded`（走远点就没数据了，得先靠近）

### POST /landmark `{"action":"remember","name":"铁矿脉"}`
| action | 参数 | 返回要点 |
|---|---|---|
| `remember` | `name`（≤40 字） | 记当前位置；**同维度 8 格内视为同一地点 → 覆盖改名+清零**，不新增 |
| `recall` | — | 同 GET /landmark |
| `verify` | `name`,`found` | found=true 清零；**连续两次 false 就遗忘** |
| `go` | `name` | 直接寻路走过去（=`/path` 到该地标），最省事 |

- 满了 24 条会挤掉最老的；`name` 必填，未知 action → 500
- 用法：**做完事就 remember**（挖完矿/盖完房/发现洞口），出门前先 recall

### POST /job `{"type":"dig_shaft","max_depth":24,"dir":"east"}`
启动一个**长任务**（进程内跑，不占用一次 HTTP 那么久）：
```json
{"ok":true,"data":{"started":true,"type":"dig_shaft","dir":"east","maxDepth":24,"start":{"x":61,"y":74,"z":-72},
 "hint":"现在可以结束本轮；用 GET /job 查进度和收尾报告"}}
```
- **dig_shaft（安全阶梯下矿）**：2 格宽、每步挖 4 格（主/副台阶+头顶净空），开挖前查 **6 处流体**（目标/头顶/脚下×2 列）+ 目标 6 邻居；**台阶下方是空腔就中止**（下面是洞窟/悬崖）；每 6 格放火把；到深度上限后扫井壁矿脉并报告
  - 参数：`max_depth` 1..24（默认 24）、`dir` north/south/east/west（缺省用她当前朝向，决定台阶往哪边走，建议 east/west 以免挖到自家房子）
- **build_hut（蓝图建房）**：`{"type":"build_hut","blueprint":"hut_small"|"hut"}`
  - hut_small 3×3 墙高 2（需 23 块）/ hut 5×5 墙高 3（需 64 块）；材料优先木板，其次圆石/石砖
  - **开工前核算材料，缺就报确切缺口**：`missing_materials: hut_small 需要 23 块 spruce_planks，当前只有 19 块，还差 4 块`
  - **选址预检**：屋内体积有实心方块（比如树）→ 直接拒绝并点名，一块都不挖
  - 清场只挖天然方块；**人造方块占用则中止**（不拆你的建筑）
  - 已在正确位置的材料块会跳过 → 中断后重新调用就是**续建**
  - `house_2f`（9×9 两层+阳台）**还没移植**，会明确报错
- **中止**：`{"action":"abort","reason":"…"}`（**会在当前那块挖完才停**，防止半破坏态）
- **单飞**：同一时间只能跑一个作业，再启 → 500 `another job is already running`
- **状态只在内存、重启清空**（地标才落盘）。看进度一律 `GET /job`，**别用 /wait**（/wait 的可等路径里没有 /job）

### POST /look `{"mode":"third","orbit":{"over":true,"dist":5}}`
看一眼（先渲染再送视觉模型），**是贵操作：≤1 次/2s、≤200 次/天、往返 5~30 秒**。
```json
{"ok":true,"data":{"frames":["G:\\feiyu-mc\\shots\\over-….jpg"],"savedTo":"G:\\feiyu-mc\\shots",
 "mode":"third","description":"石头地形…边缘有缺口，需小心坠落，附近无水和岩浆。",
 "source":"vision","visionReason":null,"tookMs":29624,"rate":{"used":3,"limit":200}}}
```
- `mode`：`first`（默认，她的眼睛）/ `third`（第三人称）
- `mode=first` 可加 `lookAt:{x,y,z}` → 先转头看那格再拍（她贴墙/背对时必用）
- `mode=third` 三种构图：
  - 鸟瞰：`{"mode":"third"}`
  - 自由环绕：`{"orbit":{"yawDeg":20,"pitchDeg":-15,"zoom":-700}}`（正=拉远，负=靠近）
  - **越肩：`{"orbit":{"over":true,"dist":4.5,"yawOffsetDeg":0,"pitchDeg":78}}`** → 角色居中、正后方，`dist` 远近、`yawOffsetDeg` 侧偏、`pitchDeg` 俯角（90=与眼同高）
- **`source` 三值必须看**：`vision`（真看见了）/ `fallback_state`（视觉失败，给的是桥状态文字）/ `capture_only`（视觉服务没配）——后两者 `description` 前面带 `[非视觉…]`
- `frames` 是**落盘路径**，主人和主持都能翻；单帧 JPEG ≤800KB、每请求 ≤3 帧
- 429：`rate_limited`（带 `retryAfterMs`）或 `daily_limit`
- ⚠️ **第三人称相机贴着地面/埋进方块时，近平面会把地面切开、透视到地下洞穴**（看起来像"屏幕下半截成了另一个世界"）。桥会自动查机位 3×3×3 邻域并抬高压角，日志里会写 `机位原本埋在方块里，俯角抬高 N°`；抬不出来时会警告 `仍可能在实心方块内`——那种帧别当证据用
- ⚠️ 走路、找路、挖矿时**不要开 /look**，它只用于"停下来验收一眼"

## 3. POST /wait 速查（契约 wait/1.1）

一次调用阻塞到条件成立或超时——**用它替换任何 `for+sleep+curl` 循环**。
```json
POST /wait {"path":"/state","condition":"invSlotsUsed >= 36","timeout_s":60}
```
- **path 五选一（精确字符串）**：`/state` `/pos` `/inv/count` `/time` `/health`；其他一律 `400 path_not_waitable`
- **condition**：单条件 `路径 op 字面量`，一个空格分隔（两个空格都拒）；op：`== != < <= > >=`
  - 排序只对数字；bool 只比 bool；字符串只比相等
  - 长度 ≤128、路径 ≤8 段、每段 ≤64 字符
- **timeout_s**：整数 1..300 缺省 60；>300 夹到 300（响应 `effective_timeout_s` 自报）；`"60"`/`60.0`/true 全拒
- **响应**：`{"contract":"wait/1.1","ok":true,"reason":"matched","matched":true,"matched_at_sample":1,"samples_total":1,"samples_ok":1,"samples_failed":0,"samples_missing":0,"samples_type_error":0,"effective_timeout_s":60,"elapsed_ms":1,"value":{…}}`
- **reason 四值怎么读**：
  - `matched` 条件成立（`matched_at_sample`=第几次采样命中）
  - `timeout` 等到超时没成立——**条件没坏，只是没等到**
  - `degraded` **看不见≠不成立**：采样失败太多（桥抖/bot 掉线），报主持别干等
  - `bad_request` 等再久也不会成立——**立刻改条件**，`detail` 告诉你哪坏了
- **detail 八个值**：path_not_waitable / request_shape（condition 非字符串 或 timeout 非法）/ expr_len(>128) / condition_grammar（语法/结尾换行/双空格）/ path_segments(>8) / path_ident_len(>64) / condition_literal（字面量写错）/ unknown_field（/inv/count 物品名拼错，**带 hint.nearest_names 最近 5 个候选**）
- **`/inv/count` v1.1 语义**：包里没这物品=数量 0 → `iron_ingot == 0` 缺货时**立刻 matched**（等清空可表达）；只有拼错才 400
- **高频示例**：
  - 等天亮：`{"path":"/time","condition":"timeOfDay < 1200","timeout_s":300}`（0–24000 刻）
  - 等背包满：`{"path":"/state","condition":"invSlotsUsed >= 36"}`
  - 等挖够：`{"path":"/inv/count","condition":"cobblestone >= 8","timeout_s":300}`
  - 等 bot 回线：`{"path":"/health","condition":"botConnected == true","timeout_s":120}`
  - 等人上线：`{"path":"/state","condition":"players 的长度不可表达——用轮询或等主持转告"}`
- 429 `too_many_waiters`：并发上限 32，只拒新的；同条件别开两个

## 4. POST /mcp（JSON-RPC 工具面）
```json
POST /mcp {"jsonrpc":"2.0","id":1,"method":"tools/list"}
POST /mcp {"jsonrpc":"2.0","id":2,"method":"tools/call","params":{"name":"mc_state","arguments":{}}}
```
- 工具：mc_state / mc_chat{text} / mc_dig{x,y,z} / mc_path{x,y,z} / mc_inv / mc_time
- initialize: `{"jsonrpc":"2.0","id":0,"method":"initialize","params":{"protocolVersion":"2024-11-05","capabilities":{},"clientInfo":{"name":"x","version":"0"}}}`
- ⚠️ 工具失败=HTTP 200 + `result.isError:true` + content 文本 `ERROR: …`（铁律 8）

## 5. 常用套路（实测跑通过的完整链）

- **砍树**：`/find spruce_log` → 取 hits 里同 x,z 的点 → `/path` 过去 → 逐格 `/dig` → **走过去捡**（掉落物不自动吸附，拾取半径 ~1.5 格，挖完必须 path 走一遍）
- **采集→合成→挖矿→建房全链**（2026-11-08 实跑）：find 树→挖 8 log→craft planks(小步×5)→craft table→equip→place→craft stick→craft wooden_pickaxe→equip→find stone→dig 石×4→path 捡→craft stone_pickaxe→dig 洞屋→place 台入洞
- **等天亮再出门**：/wait /time timeOfDay < 1200
- **背包满了**：/wait /state invSlotsUsed >= 36 → 回家整理
- **挖矿一条龙**：站到空地 → `POST /job {"type":"dig_shaft","dir":"east"}` → 结束本轮 → `GET /job` 轮询到 `running:false` → 读 `last.report`（深度、火把数、井壁矿脉）
- **盖房子一条龙**：先凑材料（砍树→`/craft spruce_planks` 一次一根）→ `POST /job {"type":"build_hut","blueprint":"hut_small"}` → 轮询 `GET /job` → `POST /look {"orbit":{"over":true,"dist":6}}` 验收外观
- **出门回家**：出门前 `POST /landmark {"action":"remember","name":"家"}`；回来 `POST /landmark {"action":"go","name":"家"}`
- **验收一眼**：`POST /look {"mode":"third","orbit":{"over":true,"dist":5}}` → 看 `source` 是不是 `vision` → 读 description

## 6. 已知边缘限制

- **`/craft` 的 count 必须小步**：一次 `count:7` 实测只出 16 块木板（7 根原木应该出 28），中途会卡渣。**永远 count=1~2 + 每步 `/inv/count` 验证**
- **`/job` 的 abort 不会打断手上那块方块**：请求发出后最晚要等当前这一步做完才退出（刻意为之，防止半破坏态）
- **第三人称相机可能贴地透视**：见 §2 的 /look 警告，桥会自动抬角，抬不动会报警
- **带 trim 纹饰的盔甲不可见**（mineflayer/minecraft-data 的 ArmorTrimMaterial 错位，PartialReadError 被吞）——普通物品无影响
- Fabric 结构 mod（本世界装了 9 套）全 registry-neutral，物品名都在原版表内；**将来装加方块/物品的 mod 会先撞 bot 身体层**（mineflayer 解析不了 modded 注册表），不是先撞 schema
- 服务器跑 Fabric 1.21.1+11 mod（含皮肤），回滚开关在主持手里
- 视觉服务在云端（`100.89.64.119:8901`，走 tailnet + Bearer），**不可用时会降级**：`source` 一定诚实标注，别把 `fallback_state` 的文字当"看见了"
