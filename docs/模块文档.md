### /wait 长轮询（契约 **wait/1.1**，2026-11-08 冻结，两侧实现全绿）

**契约真源**：`bot/contract/CONTRACT.md`（改契约流程：先改文档→加用例→两侧实现都红→再改实现）；
Python 参考：`bot/contract/wait_probe.py`；夹具：`bot/fixtures/wait_probe_cases.json`（48 条）。
**两侧全绿才算契约成立**：Node `node run_cases.js fixtures/wait_probe_cases.json`（48/48）+
Python `python contract/wait_probe.py --cases fixtures/wait_probe_cases.json`（48/48），
阳性对照 `--mutation-check` 各 7/7 变异体全被抓。

- **请求**：`POST /wait {"path":"/state","condition":"invSlotsUsed >= 36","timeout_s":60}`（`interval_s`/`poll_s` 0.5–2s 可选，默认 1）
- **WAITABLE 精确字符串五项**：`/state /pos /inv/count /time /health`；`/inv`（数组）、`/fishbot`（toggle）、带 query/斜杠变体一律 `bad_request/path_not_waitable`
- **条件语法**：单条件 `path op literal`，SP=单空格，全串匹配（结尾 `\n` 拒——JS `$` 天然拒、Python 靠 `\Z`）；排序只对数字；bool 只和 bool 比；下钻标量=type_error、键不存在=missing
- **detail 定序**：9 条检查、**8 个字符串**（`request_shape` 覆盖条件与 timeout 两处）——path_not_waitable → request_shape×2 → expr_len → condition_grammar → path_segments → path_ident_len → condition_literal → unknown_field；timeout_s 缺省 60，1..300 原样，>300 夹 300，≤0/非整数拒
- **v1.1 MAP_DEFAULT**：`/inv/count` **末段缺失按 0 求值**（「等到包里没某样东西」从此可表达：`iron_ingot == 0` 缺货即刻 matched）；静态 schema 预检只决定要不要 400，不改变求值；中间段缺失仍 missing。旧§7表把两机制混成一列是文档错（OS 主持实测钉死）
- **响应形状**（冻结）：`{contract:"wait/1", ok, reason, detail, matched, path, condition, effective_timeout_s, elapsed_ms, samples_total, samples_ok, samples_failed, samples_missing, samples_type_error, matched_at_sample, value}`；HTTP 400=bad_request / 200=其余
- **降级**：`samples_failed/total > 0.5`（严格，0.5 不算）或命中但近 3 样本（含命中样本）≥2 failed → `degraded`；优先级 bad_request > degraded > matched > timeout
- **`/inv/count` 静态 schema**：minecraft-data 1333 原版物品名；笔误→`400/unknown_field`，`hint.nearest_names` 给与输入**编辑距离最近的 5 个**（≤8，只做附加信息、绝不改 reason/detail——tablet-pet 两约束）；合法名但背包没有→按 v1.1 视为 0 求值
- **已知边界**：模组物品不在 schema 里（第一轮结构 mod 全 registry-neutral=零新物品，无影响；将来装物品 mod 时：mineflayer 身体本身也解析不了 modded 注册表，需先动身体层，schema 再按"原版∪模组表"扩——预检绝不放宽成"名字合法就行"）
- **生产挂载参数**：`makeHttpHandler({probeFn: probeBody, payloadOf: unwrap, schema: {'/inv/count': ITEM_NAMES}})`；probe 非 2xx → samples_failed；bot 掉线时 /state、/inv/count 503+data null → failed
- target_base_url：PC `http://127.0.0.1:17700` / 云 `http://127.0.0.1:47880`（同服务同路径）；**云侧端到端已验**（matched 响应体逐字段符合契约，400 路径正确）
- 真实桥回归：`node bot\test-wait.js`（8 支：matched×2/timeout/400×5，timeout 卡 3s 实际耗时）

## 已知限制

- **带 trim 纹饰的盔甲不可见**：minecraft-data 1.21.1 `ArmorTrimMaterial` registry 定义与服务端输出错位（PartialReadError），该物品在 bot 侧被丢弃。普通物品不受影响。桥层 /inv 只列解析成功项，不崩。
- Paper stdout 有缓冲延迟，状态判定走 RCON/桥端点，不依赖 stdout tail。
- 主人客户端必须先非 NeoForge（vanilla 1.21.1）进服，NeoForge 客户端版本不同连不上。
